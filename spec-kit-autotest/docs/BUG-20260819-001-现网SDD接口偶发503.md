## 复现步骤

1. 登录现网（`POST /api/v1/auth/login` 获取 Bearer token）；
2. 连续创建 SDD 项目（`POST /api/v1/sdd/projects`，body 用 `sddProjectData()`）；
3. 创建后**立即**（无等待）连续调用子接口：`tasks` / `artifacts/spec/1` / `clarify/analyze` / `implement/execute` / `archive`；
4. 记录各请求 HTTP 状态与 Content-Type。

### 方法 C：浏览器 DevTools Console 一键复现（推荐分享给非测试同事）

登录目标站后，F12 → Console，粘贴以下代码（把 `token` 换成 Network 里请求头的 `Bearer xxx`）直接回车：

```js
const token = '换成你的Bearer token';
const base = 'https://106.54.60.191/api/v1';
async function round(i) {
  const headers = { 'Content-Type': 'application/json', Authorization: `Bearer ${token}` };
  const cre = await fetch(base + '/sdd/projects', {
    method: 'POST', headers,
    body: JSON.stringify({ name: `复现-${i}-${Date.now() % 100000}`, description: '缺陷复现' }),
  });
  let id = null;
  try { const b = await cre.json(); if (cre.status === 200 && b.ok) id = b.data.id || b.data; } catch (e) {}
  console.log(`[轮${i}] 创建 → ${cre.status}${id ? ` id=${String(id).slice(0, 8)}` : ' ❌未创建'}`);
  if (!id) return;
  for (const act of ['clarify/analyze', 'implement/execute']) {
    const res = await fetch(`${base}/sdd/projects/${id}/${act}`, { method: 'POST', headers, body: '{}' });
    const ct = res.headers.get('content-type') || '';
    const hit = res.status >= 500 || ct.includes('text/html');
    console.log(`    ${act} → ${res.status}${hit ? ' ❌503/HTML命中' : ''}${ct.includes('html') ? ' (HTML页)' : ''}`);
  }
  await fetch(`${base}/sdd/projects/${id}`, { method: 'DELETE', headers }).catch(() => {});
}
(async () => { for (let i = 1; i <= 6; i++) await round(i); })();
```

> ⚠️ 注意：SDD 项目创建 body 字段是 `name` / `description`（写成 `title` 会 400 校验失败）；
> 浏览器 Console 粘贴代码若遇 Self-XSS 警告，先在 Console 输入 `allow pasting` 回车，或使用已配置的 Chrome 中文调试启动器（已关闭该警告）。
> 2026-08-19 14:54 实测：浏览器 Console 版第 1 次运行即命中 503（clarify/implement 子操作）。

### 复现率（实测数据）

**场景 A：低频单接口 ×15 次**（`GET /jobs`、`POST /sdd/projects` 各 15 次）→ **全部 200，0 失败**。接口本身在低频下稳定。

**场景 B：创建 SDD 后立即调 5 个子接口 ×8 轮（共 40 次操作）**：

| 结果 | 次数 | 占比 |
|---|---|---|
| 4xx（缺前置的受控失败，符合预期） | 23 | 57.5% |
| **503（nginx HTML 错误页）** | 7 | 17.5% |
| **503（裸）** | 2 | 5% |
| **SDD 项目创建本身 503** | 2 | （8 轮中 2 轮创建即失败） |
| 200 | 0 | 0% |

> 子接口 40 次调用中约 **22.5% 命中 503**；8 轮创建中 2 轮创建即 503。

## 实际结果 vs 预期

- **实际**：请求返回 `503 Service Temporarily Unavailable`，响应体为 nginx 默认 HTML 错误页（`<html><head><title>503 Service Temporarily Unavailable</title>`），Content-Type `text/html`——客户端 JSON 解析直接抛 `SyntaxError: Unexpected token '<'`。
- **预期**：SDD 子接口应稳定返回 JSON（200 或业务 4xx）；创建接口 200。

## 影响分析

1. **自动化回归基线无法稳定**：全量 `test:api`（约 60+ 用例）每轮随机 2~3 个 SDD/作业相关用例挂 503，无法作为可靠准出依据；
2. **用户侧影响**：高频操作 SDD（创建项目→立即看任务/产物）时偶发报错页，体验中断，重试可恢复；
3. **数据安全**：503 为服务不可用，未见数据损坏/越权迹象（S1 主要因影响面而非数据风险）。

## 初步诊断建议（供后端/运维排查）

1. **503 来自 nginx 层**（响应为 nginx 默认错误页，非后端 JSON 错误），疑似 **upstream 无可用节点 / 限流 / 后端进程瞬时抖动**：
   - 查 nginx `error.log` 中 503 时刻的 upstream 状态（`upstream timed out` / `no live upstreams` / `limit_req` 命中）；
   - 查后端服务（Java Spring Boot）对应时刻的线程池/连接池/GC 日志；
2. **触发特征**：SDD 项目创建后**立即**调子接口时高发——疑似**创建后内部状态未完全就绪**（异步初始化/事务未提交）导致子接口请求瞬间失败，后端可能返回 5xx 或网关降级；
3. 验证建议：项目创建后加 1~3 秒等待重测，若 503 消失 → 指向"创建后未就绪"竞态；若仍在 → 指向后端容量/健康检查问题；
4. **修复后验收**：连续 3 轮全量 `test:api` 无 503 波动即视为修复。
