## 缺陷 1：PDF 上传成功但解析失败

### 复现步骤

1. 构造结构有效、包含唯一测试标记的 PDF；
2. 以 `multipart/form-data` 上传，文件名扩展名为 `.pdf`，MIME 为 `application/pdf`；
3. 上传接口返回成功并生成文档 ID；
4. 使用该 ID 轮询 `GET /api/v1/docs/view`；
5. 观察 `parseStatus`。

### 实际结果

- 上传成功；
- 读取接口返回同一文档 ID；
- 解析终态为 `parseStatus=failed`；
- 文档内容无法正常读取。

### 预期结果

- 有效 PDF 应完成解析；
- `parseStatus` 应进入成功终态；
- 读取内容或预览结果应包含该文件的唯一测试标记。

## 缺陷 2：DOCX 上传成功但解析失败

### 复现步骤

1. 构造结构有效、包含唯一测试标记的 DOCX；
2. 校验 DOCX ZIP 目录、XML 结构及 CRC；
3. 以正确 DOCX MIME 上传；
4. 使用返回 ID 轮询读取接口；
5. 观察 `parseStatus`。

### 实际结果

- 上传成功；
- 文档元数据和 ID 可返回；
- 解析终态为 `parseStatus=failed`；
- 无法按预期读取 DOCX 正文。

### 预期结果

- 有效 DOCX 应完成正文抽取；
- 读取内容应包含唯一测试标记；
- 不应进入解析失败终态。

## 缺陷 3：XLSX 被错误识别为 `other`

### 复现步骤

1. 构造结构有效、包含唯一测试标记的 XLSX；
2. 校验 XLSX ZIP 目录、工作簿 XML、工作表 XML 及 CRC；
3. 使用扩展名 `.xlsx` 和 MIME `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` 上传；
4. 检查上传响应中的 `fileType`。

### 实际结果

- 上传接口成功；
- `originalName`、`fileSize` 等元数据正常；
- `fileType` 返回 `other`，未识别为 `xlsx`。

### 预期结果

- `fileType` 应返回 `xlsx`；
- 后续读取/解析流程应按电子表格处理。

## 缺陷 4：缺少 `file` 字段返回 HTTP 500

### 复现步骤

1. 调用 `POST /api/v1/docs/upload`；
2. 请求使用 multipart，但不提供 `file` 字段；
3. 保留其他普通字段，如 `scope=personal`、`docType=personal`；
4. 检查 HTTP 状态和业务错误结构。

### 实际结果

- HTTP 状态为 `500`；
- 错误码为 `INTERNAL_ERROR`；
- 返回“服务器内部错误”类信息。

### 预期结果

- 缺少必填文件属于客户端请求错误，应返回 `400` 或 `422`；
- 响应应包含明确、可诊断的字段，例如 `code`、`error` 或 `message`；
- 不应产生未捕获异常或 HTTP 500。

## 缺陷 5：伪造 PDF 被接受且无内容检测结果

### 复现步骤

1. 构造实际内容为 Markdown 的文件；
2. 将文件名设置为 `.pdf`，MIME 声明为 `application/pdf`；
3. 上传至 `POST /api/v1/docs/upload`；
4. 检查 HTTP 状态、业务结果、文件类型和内容检测字段；
5. 尝试读取该文档。

### 实际结果

- 上传接口返回 HTTP 200 且业务成功；
- 服务端接受伪造 PDF；
- 响应未提供真实内容检测类型；
- 无法证明服务端校验了 magic bytes、文件签名或真实 MIME。

### 预期结果

满足以下任一安全策略：

1. 拒绝文件，返回明确的 `400`、`415` 或 `422`；或
2. 接受文件但返回真实检测类型，且不得按 PDF 进入不安全解析路径。

## 测试框架排除证据

上述问题不是测试框架误报，证据如下：

1. `.md`、`.txt`、`.json`、`.csv` 使用同一 `ApiClient`、同一认证、同一 multipart 上传和读取链路，全部通过；
2. PDF 通过 PDF 结构工具校验，是有效单页 PDF；
3. DOCX、XLSX 均为有效 OOXML ZIP 容器，ZIP CRC、关系文件及内容 XML 已通过结构检查；
4. multipart 客户端会移除默认 JSON `Content-Type`，由 Playwright 正确生成 boundary；
5. 上传响应返回的文档 ID 会在业务断言前登记，不会因断言失败漏清理；
6. 清理校验同时检查 HTTP 状态和业务字段，`HTTP 200 + ok=false` 会挂红；
7. 文档 UI 的 Markdown 上传、卡片显示、预览读取和删除闭环通过；
8. 10 份 1MB Markdown、并发度 3 的上传和读取均成功，失败率为 0%。

## 影响分析

1. **核心格式不可用**：PDF、DOCX 无法稳定读取，XLSX 无法正确识别，文档中心无法满足常见办公文件场景；
2. **错误处理不合格**：客户端缺失必填字段触发 HTTP 500，污染服务端错误率并降低可诊断性；
3. **安全风险**：仅信任扩展名/MIME 可能允许伪造文件进入错误解析链路，增加解析器攻击面；
4. **自动化准出阻断**：文档专项保持严格失败，不能以提高阈值、skip 或弱化断言规避；
5. **用户体验受损**：页面显示上传成功，但读取或预览随后失败，形成“假成功”。

## 初步根因范围与排查建议

当前证据可以定位到平台组件边界，但没有后端源码和任务日志，不能伪造具体代码根因。

### PDF/DOCX 解析失败

建议检查：

- 文档抽取服务是否安装并启用了对应解析器；
- 解析任务日志中的异常类型、依赖缺失、超时和编码错误；
- 上传完成后异步任务是否正确取得原文件；
- `parseStatus` 从 pending/running 到成功/失败的状态机；
- 解析失败时是否保存可诊断的错误码和错误摘要。

### XLSX 类型错误

建议检查：

- 扩展名和 MIME 到内部 `fileType` 的映射表；
- 是否遗漏 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`；
- 是否错误地将未知 Office 类型统一降级为 `other`；
- 类型识别是否应结合 magic bytes/OOXML 内容结构。

### 缺文件返回 500

建议检查：

- Controller 参数是否正确声明 multipart 文件为必填；
- 缺失字段异常是否被全局异常处理器映射为 400/422；
- Service 是否在空文件对象上直接解引用；
- 错误响应是否稳定包含 `ok=false` 和诊断字段。

### 伪造文件检测

建议至少增加：

- 文件签名/magic bytes 检测；
- 扩展名、声明 MIME、检测 MIME 三方一致性校验；
- OOXML ZIP 结构和内部 content-type 校验；
- 不一致时拒绝或隔离处理，禁止直接进入高风险解析器；
- 上传大小、解压比和压缩包路径穿越防护。
