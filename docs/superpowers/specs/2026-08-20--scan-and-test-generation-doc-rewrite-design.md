# 系统扫描与测试生成方案重写设计

## 目标

将现有 1245 行说明型方案重构为可执行技术规格：减少重复，严格区分现有能力与待建设能力，补齐数据 Schema、生命周期、生成隔离、覆盖保护、错误处理、LLM 接入前置条件以及分阶段验收出口。

## 结构

正文按以下顺序组织：文档定位、事实分层、架构与信任边界、安全策略、扫描资产模型、候选用例模型、生命周期、扫描与生成流程、Playwright 生成规则、确定性门禁、LLM 约束、脱敏审计、项目集成、实施阶段、指标与验收。工具选型和示例放入附录。

## 强制规则

- 未证实的状态码、角色、字段、状态机和清理语义必须标记为假设或待确认。
- 扫描数据在持久化和进入模型前完成脱敏。
- 只有 `AUTOMATABLE` 用例可以生成代码，只有 `VALIDATED` 用例可以提升至正式测试目录。
- 生成器不得直接覆盖正式测试；人工修改必须保留，更新通过 diff 或新候选完成。
- 补充 `REJECTED`、`BLOCKED`、`STALE` 等状态及审计轨迹。
- 未确认官方 LLM 接口前，不猜测 Provider 配置；无模型时保留确定性规则生成能力。
- 默认验收不执行现网写操作、AI、破坏性或压力测试。

## 验收

- 文档不存在“四种状态却列出五项”等内部矛盾。
- 所有 `必须/禁止` 规则都有校验点或明确责任人。
- 现有能力与待建设能力清晰标注。
- 示例事实全部标注证据状态。
- 路线图包含交付物、入口条件、退出条件和默认验收命令。
