# Spec-Kit 流水线结果可信度修复设计

## 背景

当前流水线存在三处会让运行结果失真的问题：跳过项显示并计入通过、阻断门禁异常时丢失阻断属性、E2E 门禁可能读取上一次运行遗留的 JSON 报告。本次只修复这三项，不调整门禁顺序、通过率阈值、业务测试或认证刷新机制。

## 目标

1. 跳过门禁必须明确显示为 `SKIP`，且不计入通过数。
2. 阻断门禁无论正常返回失败还是抛出异常，都必须保留 `blocking=True`，由主流程返回阻断退出码 3。
3. E2E 统计只能来自本次 Playwright 运行；旧报告不得参与本次判定。

## 设计

### 1. 状态展示与汇总

在流水线入口提供统一的结果状态转换函数，优先级为 `SKIP`、`PASS`、`FAIL`。控制台和 Markdown 报告复用该函数，避免两处逻辑再次漂移。

JSON 汇总中的 `passed` 只统计 `passed=True` 且 `skipped=False` 的结果；`skipped` 单独统计。保留现有 `GateResult` 字段，避免扩大兼容性改动。

### 2. 阻断异常

`run_gate()` 捕获普通异常时，从门禁类读取 `blocking` 并写入失败结果。初始化失败仍按现有约定转为跳过，不触发阻断。

### 3. E2E 报告新鲜度

运行 npm script 前，如果固定 JSON 报告存在，则删除该文件。运行结束后只解析新生成的报告；如果没有生成报告，沿用现有的进程退出码降级判定。

删除范围仅限配置解析出的单个报告文件，不清理整个报告目录。这样既避免历史统计污染，也保留 HTML、截图和 trace 等诊断资产。

## 错误处理

- 旧 JSON 报告删除失败：门禁执行失败并返回可诊断异常，不继续使用可能过期的数据。
- npm 执行成功但未生成 JSON：不伪造用例统计，明确报告“未解析到 JSON 用例统计”，按本次进程退出码判定。
- npm 执行失败且未生成 JSON：返回失败，并附带本次 stdout/stderr 尾部。

## 测试设计

新增 Python 单元测试，至少覆盖：

1. 跳过结果格式化为 `SKIP`。
2. 报告汇总不把跳过项计入通过数。
3. 阻断门禁抛异常后结果仍为 `blocking=True`。
4. E2E 执行前删除旧报告。
5. 本次未生成报告时不读取旧统计，退化为本次退出码。

测试使用临时目录和伪门禁/伪进程，不调用目标站，不执行真实 Playwright，不碰现有报告。

## 非目标

- 不实现 Token 刷新或重新登录。
- 不调整 `min_pass_rate=0.95`。
- 不修改现有 API/UI 用例及其业务断言。
- 不改造成动态插件发现或 run ID 报告目录。

## 验收标准

- 新增测试全部通过。
- Python 现有文件可编译。
- `--dry-run` 报告中门禁展示为 `SKIP`，汇总的通过数不包含跳过数。
- 阻断门禁异常路径能够驱动主流程返回退出码 3。
- E2E 门禁无法消费执行前已存在的历史 JSON 报告。
